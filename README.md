# ИИ‑консультант для интернет‑магазина ekt.kz

Команда **JIGER** · хакатон **HACKALEM AI** · кейс партнёра ТОО «Электрокомплект» (ekt.kz):
«ИИ‑ассистент‑консультант и помощник для сайта ekt.kz».

Чат‑ассистент, который отвечает покупателю на вопросы о товарах ekt.kz по **реальным данным каталога**:
наличие по складам, цена, характеристики, ссылка на карточку товара и подбор аналогов, если позиции нет в наличии.
Работает на русском и казахском языках.

> Развёрнутой версии нет: проект запускается локально или в Docker за 5 минут (см. раздел 4).

---

## 1. Что делает проект

**Проблема (из кейса).** Чтобы узнать наличие, характеристики или аналог товара, клиент ekt.kz пишет или звонит
менеджеру. Решение о покупке затягивается, менеджеры тратят время на однотипные вопросы.

**Решение.** Единое окно чата на сайте, где ассистент:

- находит товар по артикулу, названию, бренду или характеристикам;
- отвечает, есть ли товар в наличии и **на каких складах сколько штук**;
- показывает цену, характеристики, минимальную партию и ссылку на страницу товара на ekt.kz;
- если товара нет — предлагает аналоги из каталога и объясняет, чем они отличаются;
- понимает вопросы на русском и казахском;
- отвечает только по данным каталога и не выдумывает цены и наличие (защита от «галлюцинаций» на уровне промпта и инструментов);
- отказывается отвечать на вопросы не о товарах.

Ответы приходят за 1–6 секунд (gpt‑4o‑mini, замер 23.09.2026).

## 2. Что реализовано

### Покрытие требований Must have (из ТЗ кейса)

| № | Требование ТЗ | Статус | Как проверить / где в коде |
|---|---|---|---|
| 1 | Наличие товара, характеристики, сертификаты по данным каталога | **Частично** | Наличие (общее и по складам), цена, характеристики, минимальная партия, ссылка — **да** (`app/catalog.py`, инструменты `search_products` и `get_product`). **Сертификатов в данных API ekt.kz нет** — ни одна из 400 карточек каталога их не содержит, поэтому ассистент их не выдаёт. |
| 2 | Аналоги при отсутствии товара с обоснованием | **Да** | Ассистент ищет похожие позиции в каталоге, предлагает только те, что в наличии, и объясняет отличия (`app/prompts.py`, правило 3). Проверка — артикул `310100080_` (остаток 0), см. раздел 5. |
| 3 | Условия покупки: оплата, доставка, минимальная партия | **Нет** | Источник данных об условиях покупки партнёром не предоставлен; ассистент честно отвечает, что не может сообщить условия. Минимальная партия по товару (`KRATNOST_MIN`) выдаётся. |
| 4 | Добавление в корзину только после явного подтверждения | **Да** | Корзина прототипа хранится в памяти сервера и привязана к HttpOnly cookie `ekt_session` (`app/cart.py`). Добавление в два шага: `propose_cart_add` проверяет остаток (`detail.quantity`) и кратность (`KRATNOST_MIN`) и только готовит предложение; `confirm_cart_add` переносит товар в корзину, лишь если сервер (регулярное выражение, а не промпт) нашёл в **следующем** сообщении покупателя явное «да / ок / подтверждаю / добавьте / иә / жарайды / қос». Без этого корзина не меняется; количество не превышает остаток с учётом уже лежащего в корзине. |
| 5 | Прямая ссылка на корзину/оформление заказа | **Да** | После подтверждения ассистент даёт ссылку `{PUBLIC_BASE_URL}/cart`. Страница `GET /cart` (и JSON `GET /api/cart`) собирается на сервере при каждом открытии и показывает актуальный состав: артикул, название, количество, цена, сумма, ссылка на товар. Чужая корзина по подделанной cookie не читается и не меняется. |

### Опциональные требования

| Требование | Статус | Комментарий |
|---|---|---|
| Казахский язык | **Да** | Определение казахских букв в запросе + правило промпта: ответ на языке вопроса, поиск по русскому каталогу (`app/agent.py`, `app/prompts.py`). |
| Рекомендации сопутствующих товаров | **Частично** | Ассистент предлагает альтернативы из результатов поиска; отдельного механизма «сопутствующих» нет. |
| История диалога для авторизованных | **Нет** | История хранится в браузере в рамках одной вкладки (последние 10 реплик передаются с каждым запросом). |
| Эскалация на менеджера | **Нет** | — |

### Что сделано сверх матрицы

- **Карточки товаров в чате**: фото, цена, бейдж «В наличии · N шт.» / «Нет в наличии», артикул, ссылка на ekt.kz (`static/chat.html`).
- **Контекст диалога**: id показанных товаров передаются на сервер, поэтому уточнения вроде «а в каких городах есть второй?» не требуют повторного поиска.
- **Загрузчик каталога** `fetch_catalog.py`: постранично забирает список товаров и полную карточку каждого из API ekt.kz с повторами при сбоях и атомарной записью кэша.
- **Безопасность**: секреты вырезаются из логов и ответов (`redact_secrets`), промпт запрещает выполнять инструкции из сообщений покупателя, фронтенд экранирует HTML и разрешает только http(s)‑ссылки, лимит 1000 символов на сообщение, ограничение 5 раундов вызова инструментов. Корзина доступна только по HttpOnly cookie `ekt_session` (SameSite=Lax), которую выдаёт сервер; идентификаторов корзины в теле запросов нет, подделанная cookie заменяется новой пустой сессией.
- **Устойчивость**: обработка таймаутов, лимитов и ошибок OpenAI с понятными сообщениями пользователю; сервис не падает при некорректном JSON.
- **Docker**: образ 181 МБ, запуск одной командой, healthcheck.
- **Тесты и тест‑кейсы**: 23 ручных тест‑кейса по Must have 1–5 (`docs/test-cases.xlsx`), live‑тесты API ekt.kz, офлайн‑тесты инструментов (см. раздел 4).

### Стек

| Слой | Технология |

| Язык | Python 3.11+ |

| Фронтенд | Один HTML‑файл: чистый HTML/CSS/JS без сборки и фреймворков |

| Тесты | pytest, pytest‑asyncio, respx |
| Контейнеризация | Docker, docker compose |

### Схема

```
 Браузер покупателя                    Сервер (FastAPI)                         Внешние сервисы
 ─────────────────                    ────────────────                         ───────────────
 static/chat.html  ── POST /chat ──▶  app/main.py
   message,                              │
   history[-10],                         ▼
   product_ids                        app/agent.py  (цикл агента, ≤5 раундов)
                                         │  system prompt (app/prompts.py)
                                         │  + история + контекст показанных товаров
                                         ├──────────── chat.completions ───────────▶  OpenAI API
                                         │◀─────────── tool_calls ─────────────────
                                         │
                                         ├─ search_products(query, max_results) ─┐
                                         ├─ get_product(product_id) ─────────────┤
                                         │                                       ▼
                                         │                                app/catalog.py
                                         │                                data/products.json  ◀── fetch_catalog.py ◀── https://ekt.kz/api/products
                                         ▼
 карточки товаров  ◀── {reply, products} ─┘
```

### Поток одного запроса

1. Браузер отправляет `POST /chat` с текстом вопроса, последними 10 репликами и id уже показанных товаров.
2. Сервер собирает системный промпт (правила консультанта + данные уже показанных товаров + подсказка языка) и вызывает OpenAI с описанием двух инструментов.
3. Модель вызывает `search_products` (поиск по артикулу и ключевым словам в кэше каталога) и/или `get_product` (полная карточка: описание, характеристики, минимальная партия, остатки по складам). Несколько карточек запрашиваются параллельно в одном раунде.
4. Результаты инструментов возвращаются модели; после не более чем 5 раундов модель формирует текстовый ответ.
5. Сервер отбирает товары, которые реально упомянуты в ответе, и отдаёт `{"reply": "...", "products": [...]}`.
6. Фронтенд безопасно рендерит Markdown‑ответ и превращает упомянутые товары в карточки с фото, ценой и остатком.

### Инструменты модели (function calling)

| Инструмент | Аргументы | Что возвращает |
|---|---|---|
| `search_products` | `query`, `max_results` (1–10) | До 10 товаров: id, название, артикул, цена, ссылка, фото, общий остаток, `in_stock`, склады с остатком > 0. Точное совпадение артикула ранжируется первым. |
| `get_product` | `product_id` | Полная карточка: описание, характеристики (`properties`), минимальная партия (`min_batch`), остатки по складам. |
| `propose_cart_add` | `product_id`, `quantity` | Шаг 1 корзины: проверяет товар, остаток и кратность, сохраняет предложение (в корзину ничего не попадает) и возвращает артикул, название, цену, количество и сумму для показа покупателю. При нарушении — `error` с `max_quantity` / `suggested_quantity`. |
| `confirm_cart_add` | — | Шаг 2: добавляет предложение в корзину только если в текущем сообщении покупателя сервер нашёл явное согласие; иначе `error` «нет явного подтверждения». Возвращает состав корзины и `cart_url`. |
| `cancel_cart_proposal` | — | Снимает неподтверждённое предложение. |
| `get_cart` | — | Текущий состав корзины покупателя и `cart_url`. |

## 4. Порядок установки и запуска

### Требования

- Python 3.11 или новее (либо Docker);
- ключ OpenAI API;
- доступ к API ekt.kz нужен **только** для обновления каталога: готовый кэш `data/products.json` уже лежит в репозитории.

### Переменные окружения (`.env`)

```sh
cp .env.example .env
```

| Переменная | Обязательна | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | да | ключ OpenAI |
| `MODEL` | нет | модель OpenAI, по умолчанию `gpt-4o-mini` |
| `EKT_API_USER`, `EKT_API_PASSWORD` | только для `fetch_catalog.py` | Basic Auth к `https://ekt.kz/api/products` |
| `PUBLIC_BASE_URL` | нет | адрес, по которому покупатель открывает сайт; из него собирается ссылка на корзину `{PUBLIC_BASE_URL}/cart`, по умолчанию `http://localhost:8000` (при `https://` cookie сессии выдаётся с флагом Secure) |

### Вариант A — uv (рекомендуется)

```sh
git clone git@github.com:BAITC-Hacks/hack-c471837d-jiger.git
cd hack-c471837d-jiger
cp .env.example .env            # вписать OPENAI_API_KEY
uv sync --locked
uv run python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Вариант B — venv + pip

```sh
python -m venv .venv
source .venv/bin/activate       # Windows PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### Вариант C — Docker

```sh
cp .env.example .env            # вписать OPENAI_API_KEY
docker compose up --build
```

Папка `data/` монтируется в контейнер, healthcheck опрашивает `/docs`.

После запуска откройте **http://localhost:8000** — чат. Swagger‑документация API: **http://localhost:8000/docs**.

### Обновление каталога (по желанию)

```sh
uv run python fetch_catalog.py --max-pages 20    # нужны EKT_API_USER / EKT_API_PASSWORD в .env
```

Скрипт постранично забирает список товаров и полную карточку каждого, повторяет запросы при сбоях и атомарно заменяет `data/products.json`. Без кэша приложение не стартует и печатает подсказку запустить этот скрипт.

### Тесты

```sh
uv run --with pytest --with pytest-asyncio --with respx python -m pytest        # офлайн‑тесты
uv run --with pytest --with pytest-asyncio python -m pytest -o "addopts=" -m live tests/test_ekt_api.py   # live‑тесты API ekt.kz (нужны EKT_USER/EKT_PASSWORD)
```

Состояние на 23.09.2026: `tests/test_ekt_api.py` — 11 live‑проверок API ekt.kz (авторизация, пагинация, поля карточки).
`tests/test_tools_product.py` и `tests/test_tools_analogs.py` написаны как контракты «впереди кода»: из 9 офлайн‑тестов
проходит 1, остальные 8 фиксируют ещё не реализованное поведение (отдельный инструмент `find_analogs`, поля `properties`
в результатах поиска, строгий «не найдено» для несуществующего артикула). Это осознанный TDD‑задел, а не регрессия.

### Сценарии для жюри (реальные ответы от 23.09.2026, сокращены)

**1. Must have 1 — наличие и характеристики по артикулу.**
Вопрос: `Есть ли в наличии товар с артикулом 010400570_? Расскажи характеристики и на каких складах он есть.`
Ожидание: название, цена 2210 ₸, остатки по складам, ссылка на ekt.kz.
Ответ (4,4 с):

> Товар с артикулом `010400570_` — это `12125 АВ (1ф) 25А Schneider Electric (12)`.
> **Характеристики:** цена 2210 тенге, ток 25 А, 1‑фазный.
> **Наличие на складах:** Алматы — 1182 шт., Караганда — 19 шт., Нур‑Султан — 58 шт., Шымкент (ул. Байдукова) — 49 шт., Шымкент (Тассай) — 44 шт.
> Для подробной информации перейдите по [ссылке на товар](https://ekt.kz/catalog/novinki/shchitovoe_oborudovanie_aktsiya_10/12125_av_1f_25a_schneider_electric_12/).

**2. Must have 2 — аналог для товара с нулевым остатком.**
Вопрос: `Нужен дифавтомат 1P+N 16А 30мА, артикул 310100080_. Есть в наличии? Если нет — предложи аналог и объясни почему.`
Ожидание: сообщение об отсутствии и минимум один аналог в наличии с обоснованием.
Ответ (5,9 с):

> К сожалению, дифавтомат `007886 Диф.авт. 1p+N 16А (30мА) 411002 Legrand` с артикулом `310100080_` сейчас отсутствует на складах.
> Вот подходящие альтернативы:
> 1. `25616 УЗО АВДТ (1P+N) 16А (30мА) Schneider Electric` — 33 110 тг. — с теми же характеристиками… В наличии: Алматы — 130 шт., Шымкент (ул. Байдукова) — 5 шт., Караганда — 3 шт., Нур‑Султан — 2 шт.
> 2. `411002 УЗО АВДТ DX3 (1П+Н) 16А (30мA‑AC) Legrand` — 32 020 тг. — аналог от того же производителя… В наличии: Алматы — 31 шт., Шымкент (ул. Байдукова) — 6 шт., Нур‑Султан — 8 шт.

**3. Must have 3 — условия покупки (не реализовано, честный отказ).**
Вопрос: `Какие условия оплаты и доставки? Есть минимальная партия?`
Ответ (1,6 с):

> К сожалению, я не могу предоставить информацию об условиях оплаты и доставки, но могу помочь вам выбрать электротовары…

**4. Must have 4–5 — корзина: явное подтверждение и ссылка.**
Вопрос: `Добавь в корзину 5 шт. товара с артикулом 030300426_` (остаток в каталоге — 3 шт.).
Ответ (реальный, 23.09.2026): ассистент находит товар, вызывает `propose_cart_add` на доступные 3 шт. и спрашивает:

> Я нашёл товар с артикулом `030300426_`:
> - `020-108 Коробка распаячная для полых стен с пласт. Лапками и крышкой 110/50.2.2` — 350 тенге — 3 штуки, общая сумма 1050 тенге.
>
> Подтвердите добавление этого товара в корзину?

`GET /api/cart` в этот момент пуст. После ответа `да` сервер находит явное согласие в сообщении, `confirm_cart_add` переносит 3 шт. в корзину:

> Товар `020-108 Коробка распаячная для полых стен с пласт. Лапками и крышкой 110/50.2.2` в количестве 3 штук был успешно добавлен в корзину на сумму 1050 тенге.
> Вы можете просмотреть свою корзину по следующей ссылке: [Корзина](http://localhost:8000/cart).

Страница `/cart` показывает 3 шт. на 1 050 ₸, вопрос «Что у меня в корзине?» отвечается через `get_cart`, а клиент без этой cookie видит пустую корзину. Без «да» (вопрос, отказ, другое сообщение) состав не меняется; «нет» снимает предложение.

`027022 АВ DRX125 MT 3ф 25А` — поиск по ключевым словам не всегда учитывает число полюсов (см. ограничения).

Пустое сообщение или сообщение длиннее 1000 символов возвращает подсказку без обращения к OpenAI; некорректный JSON — HTTP 422 с текстом ошибки в поле `reply`.

### Проверка корзины через API

Cookie сессии `ekt_session` выдаётся первым `POST /chat`; храним её в `cookies.txt`. Предложение добавления сервер держит у себя, поэтому «да» работает даже с пустой `history`.

```sh
curl -s -c cookies.txt -b cookies.txt http://localhost:8000/chat -H 'Content-Type: application/json' \
  -d '{"message": "Добавь в корзину 5 шт. товара с артикулом 030300426_", "history": [], "product_ids": []}'
curl -s -b cookies.txt http://localhost:8000/api/cart        # {"items": [], "count": 0, ...} — до подтверждения пусто
curl -s -c cookies.txt -b cookies.txt http://localhost:8000/chat -H 'Content-Type: application/json' \
  -d '{"message": "да", "history": [], "product_ids": []}'
curl -s -b cookies.txt http://localhost:8000/api/cart        # {"items": [{"article": "030300426_", "qty": 3, "total": 1050, ...}], "total": 1050, ...}
curl -s http://localhost:8000/api/cart                       # без cookie — пустая корзина
```

Страница для покупателя — `http://localhost:8000/cart` (та же cookie в браузере).

## 6. Используемые данные и внешние сервисы

### Каталог ekt.kz

- **Источник:** тестовый API партнёра `https://ekt.kz/api/products?page=N` (Basic Auth, 20 позиций на страницу) и карточка товара по `url_api_detail` (`/api/products/detail?id=…`). Снимки ответов API лежат в `tests/fixtures/api_*.json`.
- **Кэш:** `data/products.json` — 400 товаров (первые 20 страниц), снимок от 23.09.2026. В наличии 240 позиций, с нулевым остатком 160; 24 склада (Алматы, Нур‑Султан, Караганда, Шымкент, Тараз, Атырау, Актау, Усть‑Каменогорск, Талдыкорган и др.).
- **Поля записи:** `id`, `name`, `article`, `price` (тенге), `url`, `image`, `detail.description`, `detail.quantity`, `detail.stores[]{name, quantity}`, `detail.properties` (характеристики Bitrix: `NOMINALNYY_TOK`, `NOMINALNOE_NAPRYAZHENIE`, `KOLICHESTVO_POLYUSOV`, `KRATNOST_MIN`, `TORGOVAYA_MARKA` и др.). Служебные свойства (`CML2_*`, `SLIDER_PHOTOS` и т.п.) отфильтровываются перед передачей модели.
- **Бренды в выборке:** Legrand, Schneider Electric, T‑Plast, WAGO, ЗЭТАРУС, DEKraft, UNIT и др.
- **Чего в данных нет:** сертификатов, категорий верхнего уровня (`category` пустое; у части товаров категория есть в `properties.KATEGORIYA`), условий оплаты и доставки. Данные партнёра используются как есть, без анонимизации: персональных данных в каталоге нет.

### OpenAI

- Chat Completions с function calling; модель из `MODEL` (по умолчанию `gpt-4o-mini`), таймаут 30 с, 1 повтор, до 800 токенов ответа, до 5 раундов инструментов на один вопрос.
- В OpenAI уходят: системный промпт, последние 10 реплик диалога, вопрос покупателя и результаты поиска по каталогу. Платёжные и персональные данные не запрашиваются и не передаются.

### Тестовые данные

- `tests/fixtures/catalog_small.json` — 15 синтетических товаров (в наличии, с нулевым остатком, с «сертификатами», с малым остатком) для офлайн‑тестов;
- `tests/fixtures/terms.md` — **вымышленные** условия покупки для тестов, в приложении не используются.

## 7. Известные ограничения

1. **Корзина — прототип**: хранится в памяти одного процесса сервера (теряется при перезапуске), не интегрирована с корзиной сайта на Bitrix, оформление заказа не реализовано — ссылка ведёт на страницу `/cart` прототипа. Для интеграции достаточно заменить хранилище в `app/cart.py` на вызовы API корзины сайта, логика подтверждения останется прежней. Подтверждение принимается только следующим сообщением после предложения: если покупатель сначала спросил о другом, ассистент повторит предложение и вопрос.
2. **Условия покупки не реализованы** (Must have 3): нет источника данных об оплате, доставке и минимальной сумме заказа; ассистент честно отказывается их называть.
3. **Сертификатов нет в данных** API — ассистент не может их показать.
4. **Каталог — статический снимок** 400 товаров, обновляется вручную запуском `fetch_catalog.py`; остатки и цены не в реальном времени. Полный каталог ekt.kz заметно больше, поэтому ассистент говорит «не нашёл в загруженном каталоге», а не «нет в магазине».
5. **Поиск по ключевым словам**, а не семантический: запрос ранжируется по совпадению слов и точному артикулу. Точность выбора зависит от модели; в казахском примере выше был предложен трёхполюсный автомат вместо однополюсного.
6. **Вложения (фото, Excel, Word, PDF) не поддерживаются** — только текст.
7. **История диалога живёт в браузере** в рамках открытой вкладки и не сохраняется на сервере; авторизации пользователей нет.
8. **Нет эскалации на менеджера** и рекомендаций сопутствующих товаров как отдельной функции.
9. **CORS открыт для всех источников** и нет ограничения частоты запросов — для демонстрации; перед встраиванием в сайт нужно закрыть.
10. **Автотесты частично падают по замыслу**: 8 из 9 офлайн‑тестов описывают ещё не реализованные контракты (см. раздел 4).
11. Ответ зависит от доступности OpenAI: при таймауте или лимите пользователь получает сообщение «Сервис перегружен, попробуйте через минуту».
