# ИИ‑консультант для интернет‑магазина ekt.kz

Команда **JIGER** · хакатон **HACKALEM AI** · кейс партнёра ТОО «Электрокомплект» (ekt.kz):
«ИИ‑ассистент‑консультант и помощник для сайта ekt.kz».

Чат‑ассистент, который отвечает покупателю на вопросы о товарах ekt.kz по **реальным данным каталога**
(наличие по складам, цена, характеристики, ссылка на карточку), подбирает аналоги, если позиции нет,
и **добавляет товар в корзину только после явного подтверждения** покупателя с проверкой остатка.
Работает на русском и казахском языках.

> Развёрнутой версии нет: проект запускается локально или в Docker за 5 минут (раздел 4).

---

## 1. Что делает проект

**Проблема (из кейса).** Чтобы узнать наличие, характеристики или аналог товара, клиент ekt.kz пишет или звонит
менеджеру. Решение о покупке затягивается, менеджеры тратят время на однотипные вопросы.

**Решение.** Единое окно чата на сайте, где ассистент:

- находит товар по артикулу, названию, бренду, характеристикам, цене («до 3000 тенге») и разделу каталога;
- отвечает, есть ли товар в наличии и **на каких складах сколько штук**;
- показывает цену, характеристики, минимальную партию и ссылку на страницу товара на ekt.kz;
- если товара нет — предлагает аналоги из каталога и объясняет, чем они отличаются;
- по просьбе покупателя добавляет товар в корзину **строго в два шага**: предложение → явное «да»,
  с проверкой остатка и кратности на сервере, и даёт прямую ссылку на корзину;
- понимает вопросы на русском и казахском;
- отвечает только по данным каталога и не выдумывает цены и наличие;
- отказывается отвечать на вопросы не о товарах.

Ответы приходят за 1–6 секунд (gpt‑4o‑mini, замер 23.09.2026).

## 2. Что реализовано

### Покрытие требований Must have (из ТЗ кейса)

| № | Требование ТЗ | Статус | Как реализовано / как проверить |
|---|---|---|---|
| 1 | Наличие товара, характеристики, сертификаты по данным каталога | **Частично** | Наличие (общее и по складам), цена, характеристики, минимальная партия, ссылка — **да** (инструменты `search_products`, `get_product`). **Сертификатов в данных API ekt.kz нет** — ни одна из 400 карточек каталога их не содержит, поэтому ассистент их не выдаёт. Проверка — артикул `010400570_`, раздел 5. |
| 2 | Аналоги при отсутствии товара с обоснованием | **Да** | Ассистент предлагает только позиции в наличии из результатов поиска и объясняет отличия (`app/prompts.py`). Дополнительно — детерминированный инструмент `find_analogs` (`app/analogs.py`): до 5 товаров той же категории с остатком > 0 и полем `reason`. Проверка — артикул `310100080_` (остаток 0), раздел 5. |
| 3 | Условия покупки: оплата, доставка, минимальная партия | **Да** | Условия и контакты лежат в `data/terms.md` (собраны с публичных страниц ekt.kz «Доставка и оплата», «Как сделать заказ», «Условия возврата и обмена», «Контакты» 23.09.2026; партнёру достаточно править этот файл, он перечитывается без перезапуска). Блок попадает в системный промпт как единственный источник: чего в нём нет, ассистент не выдумывает, а направляет к менеджеру (`app/terms.py`, правила 11–13 в `app/prompts.py`). Минимальная партия по товару (`KRATNOST_MIN`) выдаётся и учитывается при добавлении в корзину. |
| 4 | Добавление в корзину только после явного подтверждения, с учётом количества и наличия | **Да** | Корзина прототипа хранится в памяти сервера и привязана к HttpOnly‑cookie `ekt_session` (`app/cart.py`). Два шага: `propose_cart_add` проверяет остаток и кратность и только готовит предложение (в корзину ничего не попадает); `confirm_cart_add` переносит товар в корзину, лишь если сервер (регулярное выражение, а не промпт) нашёл в **следующем** сообщении покупателя явное «да / ок / подтверждаю / добавьте / иә / жарайды / қос». Количество не может превысить остаток с учётом уже лежащего в корзине. Проверка — раздел 5, сценарии 4–6. |
| 5 | Прямая ссылка на корзину/оформление заказа | **Да** | После подтверждения ассистент даёт ссылку `{PUBLIC_BASE_URL}/cart`. Страница `GET /cart` (и JSON `GET /api/cart`) собирается на сервере при каждом открытии и показывает актуальный состав: артикул, название, количество, цена, сумма, ссылка на товар. Чужая корзина по подделанной cookie не читается и не меняется. |

### Опциональные требования

| Требование | Статус | Комментарий |
|---|---|---|
| Казахский язык | **Да** | Определение казахских букв в запросе + правило промпта: ответ на языке вопроса, поиск по русскому каталогу; слова подтверждения корзины («иә», «жарайды», «қос») распознаются. |
| Рекомендации сопутствующих товаров | **Частично** | Ассистент предлагает альтернативы и «показать ещё» по фильтрам; отдельного механизма «сопутствующих» нет. |
| История диалога для авторизованных | **Нет** | История хранится в браузере в рамках открытой вкладки (последние 10 реплик передаются с каждым запросом); корзина живёт в cookie‑сессии до 7 дней бездействия. |
| Эскалация на менеджера | **Да** | Правило промпта: крупный опт, скидки и спецусловия, тендеры, поставка под заказ, рекламации, договор или вопрос вне каталога и условий — ассистент говорит, что это решает менеджер, и даёт контакты из `data/terms.md` (телефоны, WhatsApp, e-mail и адреса филиалов, портал B2B), ничего не выдумывая. |

### Что сделано сверх матрицы

- **Карточки товаров в чате**: фото, цена, бейдж «В наличии · N шт.» / «Нет в наличии», артикул, ссылка на ekt.kz; кнопка «Корзина» в шапке (`static/chat.html`).
- **Фильтры и пагинация поиска**: только в наличии, диапазон цен, раздел каталога, «покажи ещё» (`offset`, `total`); инструмент `list_categories` предлагает реальные разделы, если запрошенной категории нет.
- **Контекст диалога**: id показанных товаров и состав корзины передаются модели, поэтому уточнения вроде «а в каких городах есть второй?» или «что у меня в корзине?» не требуют повторного поиска.
- **Загрузчик каталога** `fetch_catalog.py`: постранично забирает список товаров и полную карточку каждого из API ekt.kz с повторами при сбоях и атомарной записью кэша.
- **Безопасность**: секреты вырезаются из логов и ответов (`redact_secrets`); промпт запрещает выполнять инструкции из сообщений покупателя; фронтенд и страница корзины экранируют HTML и разрешают только http(s)‑ссылки; идентификатор корзины выдаёт сервер (HttpOnly, SameSite=Lax), в теле запросов его нет, подделанная cookie заменяется новой пустой сессией; лимит 1000 символов на сообщение, не более 5 раундов инструментов. Промпт запрещает запрашивать и предлагать сохранить платёжные данные (номер карты, CVV, PIN, коды из SMS, реквизиты) — на такие просьбы ассистент объясняет способы оплаты из условий покупки.
- **Приватность логов**: по умолчанию в лог попадают только длина сообщения, id ответа OpenAI и имена инструментов; текст сообщений покупателя, аргументы инструментов и ответы пишутся только при `LOG_LEVEL=DEBUG`.
- **Скорость и актуальность**: каталог читается с диска один раз при старте и кэшируется в памяти с индексами `id → товар` и `артикул → товар` (точный поиск по артикулу за O(1)); файл перечитывается при замене (`reload_catalog()`). Перед подтверждением добавления в корзину остаток товара сверяется с API ekt.kz (таймаут 5 с, при заданных `EKT_API_USER`/`EKT_API_PASSWORD`); если API недоступен, используется кэш и ассистент говорит об этом покупателю.
- **Устойчивость**: понятные сообщения при таймаутах, лимитах и ошибках OpenAI; если ответ с предложением не дошёл до покупателя, предложение снимается.
- **Docker**: образ 181 МБ, запуск одной командой, healthcheck.
- **Тесты и тест‑кейсы**: 74 офлайн‑теста (инструменты каталога, аналоги, корзина с подменённой моделью), 11 live‑тестов API ekt.kz, 23 ручных тест‑кейса по Must have 1–5 (`docs/test-cases.xlsx`).

### Схема

```
 Браузер покупателя                     Сервер (FastAPI)                            Внешние сервисы
 ─────────────────                     ────────────────                            ───────────────
 static/chat.html ── POST /chat ─────▶ app/main.py ──── cookie ekt_session ──▶ app/cart.py (in-memory корзины)
   message, history[-10],                  │                                          ▲
   product_ids                             ▼                                          │
                                       app/agent.py  (цикл агента, ≤5 раундов)        │
                                           │ system prompt (app/prompts.py)           │
                                           │ + показанные товары + состав корзины     │
                                           ├──── chat.completions ───────────────────────────▶ OpenAI API
                                           │◀─── tool_calls ────────────────────────────────
                                           ├─ search_products / list_categories / get_product / find_analogs
                                           │        └──▶ app/catalog.py ──▶ data/products.json ◀── fetch_catalog.py ◀── https://ekt.kz/api/products
                                           ├─ propose_cart_add / confirm_cart_add / cancel_cart_proposal / get_cart ─┘
                                           ▼
 карточки товаров ◀── {reply, products} ───┘
 страница корзины ◀── GET /cart, GET /api/cart ── app/cart_page.py
```

### Поток одного запроса

1. Браузер отправляет `POST /chat` с текстом вопроса, последними 10 репликами и id уже показанных товаров; cookie `ekt_session` идентифицирует корзину (выдаётся сервером при первом запросе).
2. Сервер собирает системный промпт: правила консультанта, условия покупки и контакты из `data/terms.md`, данные уже показанных товаров, текущий состав корзины и ожидающее подтверждения предложение, подсказка языка.
3. Модель вызывает инструменты каталога (`search_products` с фильтрами, `get_product`, `list_categories`, `find_analogs`) и корзины (`propose_cart_add` → `confirm_cart_add` / `cancel_cart_proposal`, `get_cart`). Несколько карточек запрашиваются параллельно в одном раунде.
4. Результаты инструментов возвращаются модели; после не более чем 5 раундов модель формирует текстовый ответ.
5. Сервер отбирает товары, реально упомянутые в ответе, и отдаёт `{"reply": "...", "products": [...]}`.
6. Фронтенд безопасно рендерит Markdown‑ответ и превращает упомянутые товары в карточки с фото, ценой и остатком.

### Инструменты модели (function calling)

| Инструмент | Аргументы | Что делает |

Точный артикул → первым, затем товары в наличии, затем по релевантности и цене. |

## 4. Порядок установки и запуска

### Требования

- Python 3.11 или новее (либо Docker);
- ключ OpenAI API;
- доступ к API ekt.kz нужен **только** для обновления каталога: готовый кэш `data/products.json` уже лежит в репозитории.

### Переменные окружения (`.env`)

```sh
cp .env.example .env
```

| Переменная | Обязательна | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | да | ключ OpenAI |
| `MODEL` | нет | модель OpenAI, по умолчанию `gpt-4o-mini` |
| `PUBLIC_BASE_URL` | нет | адрес, по которому покупатель открывает сайт; из него собирается ссылка на корзину `{PUBLIC_BASE_URL}/cart`, по умолчанию `http://localhost:8000` (при `https://` cookie сессии выдаётся с флагом Secure) |
| `EKT_API_USER`, `EKT_API_PASSWORD` | нет | Basic Auth к `https://ekt.kz/api/products`: нужны для `fetch_catalog.py` и для проверки свежего остатка перед добавлением в корзину (без них остаток берётся из кэша) |
| `LOG_LEVEL` | нет | `DEBUG` — писать в лог текст сообщений, аргументы инструментов и ответы; иначе только длины, id ответа OpenAI и имена инструментов |
| `ALLOWED_ORIGINS` | нет | источники для CORS через запятую; по умолчанию `*` (демо, без cookie между доменами). Для сайта партнёра: `ALLOWED_ORIGINS=https://ekt.kz,https://www.ekt.kz` — тогда включается `allow_credentials`, и cookie корзины принимается с этих доменов |

### Вариант A — uv (рекомендуется)

```sh
git clone git@github.com:BAITC-Hacks/hack-c471837d-jiger.git
cd hack-c471837d-jiger
cp .env.example .env            # вписать OPENAI_API_KEY
uv sync --locked
```

Скрипт постранично забирает список товаров и полную карточку каждого, повторяет запросы при сбоях

### Проверка корзины через API

Cookie сессии `ekt_session` выдаётся первым `POST /chat`; храним её в `cookies.txt`. Предложение добавления сервер держит у себя,

```sh
curl -s -c cookies.txt -b cookies.txt http://localhost:8000/chat -H 'Content-Type: application/json' \

curl -s -b cookies.txt http://localhost:8000/api/cart        # {"items": [{"article": "030300426_", "qty": 3, "total": 1050, ...}], "total": 1050, ...}
```

## 6. Используемые данные и внешние сервисы

### Каталог ekt.kz

- **Источник:** тестовый API партнёра `https://ekt.kz/api/products?page=N` (Basic Auth, 20 позиций на страницу)
  и карточка товара `https://ekt.kz/api/products/detail?id=…`. Снимки ответов API лежат в `tests/fixtures/api_*.json`.
- **Кэш:** `data/products.json` — 400 товаров (первые 20 страниц), снимок от 23.09.2026. В наличии 240 позиций,
  с нулевым остатком 160; 24 склада (Алматы, Нур‑Султан, Караганда, Шымкент, Тараз, Атырау, Актау, Усть‑Каменогорск, Талдыкорган и др.).
- **Поля записи:** `id`, `name`, `article`, `price` (тенге), `url`, `image`, `detail.description`, `detail.quantity`,
  `detail.stores[]{name, quantity}`, `detail.properties` (характеристики Bitrix: `NOMINALNYY_TOK`, `NOMINALNOE_NAPRYAZHENIE`,
  `KOLICHESTVO_POLYUSOV`, `KRATNOST_MIN`, `TORGOVAYA_MARKA`, `KATEGORIYA` и др.). Раздел каталога выводится из URL товара
  (`/catalog/<раздел>/<подраздел>/…`). Служебные свойства (`CML2_*`, `SLIDER_PHOTOS` и т.п.) отфильтровываются перед передачей модели.
- **Бренды в выборке:** Legrand, Schneider Electric, T‑Plast, WAGO, ЗЭТАРУС, DEKraft, UNIT и др.
- **Чего в данных нет:** сертификатов, условий оплаты и доставки; поле `KATEGORIYA` заполнено только у 56 из 400 товаров.
  Данные партнёра используются как есть; персональных данных в каталоге нет.

### OpenAI

- Chat Completions с function calling; модель из `MODEL` (по умолчанию `gpt-4o-mini`), таймаут 30 с, 1 повтор,
  до 800 токенов ответа, до 5 раундов инструментов на один вопрос.
- В OpenAI уходят: системный промпт, последние 10 реплик диалога, вопрос покупателя, результаты поиска по каталогу
  и состав корзины (артикулы и количества). Платёжные и персональные данные не запрашиваются и не передаются.

### Корзина

- Хранится в памяти процесса: словарь «id сессии → позиции», TTL 7 дней бездействия, не более 10 000 сессий.
- Идентификатор сессии (`secrets.token_urlsafe`) выдаёт сервер и хранит в HttpOnly‑cookie `ekt_session`; неизвестная cookie заменяется новой.

### Условия покупки и контакты

- `data/terms.md` — оплата, доставка, возврат, оптовые условия и контакты филиалов, собранные с публичных страниц ekt.kz 23.09.2026. Файл читается при старте и перечитывается при изменении; в промпт попадают первые 6000 символов. Если файла нет, ассистент честно говорит, что условия не заданы, и предлагает обратиться в магазин через сайт.

### Тестовые данные

- `tests/fixtures/catalog_small.json` — 15 синтетических товаров (в наличии, с нулевым остатком, с «сертификатами», с малым остатком) для офлайн‑тестов;
- `tests/fixtures/terms.md` — **вымышленные** условия покупки для тестов, в приложении не используются.

## 7. Известные ограничения

1. **Корзина — прототип**: хранится в памяти одного процесса сервера (теряется при перезапуске, не разделяется между экземплярами), не интегрирована с корзиной сайта на Bitrix, оформление заказа не реализовано — ссылка ведёт на страницу `/cart` прототипа. Для интеграции достаточно заменить хранилище в `app/cart.py` на вызовы API корзины сайта, логика подтверждения останется прежней. Подтверждение принимается только следующим сообщением после предложения: если покупатель сначала спросил о другом, ассистент повторит предложение и вопрос.
2. **Условия покупки — снимок публичных страниц ekt.kz** от 23.09.2026 в `data/terms.md`, а не официальная выгрузка партнёра; перед показом клиентам файл должен проверить сотрудник магазина. Ассистент отвечает только по нему и отправляет к менеджеру, если ответа в файле нет.
3. **Сертификатов нет в данных** API — ассистент не может их показать.
4. **Каталог — статический снимок** 400 товаров, обновляется вручную запуском `fetch_catalog.py` (сервер подхватывает новый файл без перезапуска); в поиске и карточках остатки и цены из снимка. Свежий остаток по API запрашивается только перед подтверждением добавления в корзину. Полный каталог ekt.kz заметно больше, поэтому ассистент говорит «не нашёл в загруженном каталоге», а не «нет в магазине».
5. **Поиск по ключевым словам**, а не семантический; точность выбора зависит от модели. В казахском примере предложен трёхполюсный автомат вместо однополюсного. При просьбе «добавь в корзину» товар с нулевым остатком модель может искать только среди товаров в наличии и ответить «не нашёл» вместо «нет в наличии, вот аналог».
6. **`find_analogs` работает только для товаров с заполненной категорией `KATEGORIYA`** (56 из 400); для остальных аналоги подбирает модель по результатам поиска.
7. **Явное согласие определяется по словам** («да», «ок», «подтверждаю», «добавьте», «иә»…) и отменяется словами отказа («нет», «не надо», «но»); нестандартные формулировки потребуют переспроса.
8. **Вложения (фото, Excel, Word, PDF) не поддерживаются** — только текст.
9. **История диалога живёт в браузере** в рамках открытой вкладки; авторизации пользователей нет.
10. **Нет рекомендаций сопутствующих товаров** как отдельной функции; эскалация на менеджера — только текстом с контактами, без передачи диалога в CRM.
11. **CORS по умолчанию открыт** (`ALLOWED_ORIGINS=*`) и нет ограничения частоты запросов — для демонстрации; для сайта задайте `ALLOWED_ORIGINS=https://ekt.kz,https://www.ekt.kz`. Ссылка на корзину корректна только при заданном `PUBLIC_BASE_URL`.
12. Ответ зависит от доступности OpenAI: при таймауте или лимите пользователь получает сообщение «Сервис перегружен, попробуйте через минуту».
