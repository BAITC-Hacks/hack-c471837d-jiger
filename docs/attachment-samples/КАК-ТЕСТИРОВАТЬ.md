# Проверка вложений в чате

В этой папке — 15 готовых файлов для ручного тестирования. Артикулы взяты из
`data/products.json`; ожидаемые остатки относятся к этому локальному кэшу.
После обновления каталога сверяйте их заново. Снимок ожидаемых результатов и
контрольная сумма каталога записаны в `expected-results.json`.

## Быстрая проверка за 5 минут

1. Если сервер ещё не запущен, откройте PowerShell в корне `hack-c471837d-jiger`:

   ```powershell
   .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
   ```

   Для ответов модели нужен `OPENAI_API_KEY` в `.env` внутри проекта или в
   окружении сервера. Файлы сами по себе ключей не содержат.

2. Откройте <http://127.0.0.1:8000/>. Нажмите **Прикрепить** и выберите
   `01-specification.xlsx`. **Оставьте поле сообщения пустым** и отправьте.
3. Ассистент должен распознать 5 позиций с двух листов, проверить их через
   `search_products`, сообщить наличие и предложить добавление с подтверждением.
   Сверьте результат с таблицей ниже. Без вашего подтверждения корзина не меняется.
4. Обновите страницу для нового контекста. Приложите `05-product.jpg` и напишите:

   > Что за товар на фото? Найди его в каталоге по названию или маркировке.

5. Попробуйте выбрать одновременно 4 файла, затем `14-too-large.pdf`.
   Интерфейс должен показать понятные ошибки и не отправить запрос.

Обновление страницы очищает историю чата, но не корзину, привязанную к cookie.
Для независимой проверки корзины используйте новое приватное окно браузера.

## Какие позиции должны быть найдены

Файлы `01`, `02`, `03`, `04` и `07` описывают **один и тот же** список:

| Артикул | Требуется | Остаток в кэше | Ожидаемый результат |
|---|---:|---:|---|
| `200300273_` | 2 | 36 | Автомат Legrand DRX125, 40 А; количества хватает. |
| `200300274_` | 3 | 33 | Автомат Legrand DRX125, 50 А; количества хватает. |
| `030300426_` | 5 | 3 | Коробка распаячная; не хватает 2 шт. Нельзя обещать все 5. |
| `310100080_` | 1 | 0 | Товар найден, но остаток нулевой; возможны проверенные аналоги. |
| `TEST-ATTACHMENT-NOT-FOUND-0001` | 1 | — | Артикул не найден; нельзя подменять его похожим товаром. |

Начальные нули и завершающие подчёркивания должны сохраняться. Наличие и цены
ассистент должен брать из каталога: в накладных они намеренно не указаны.
Проверяется смысл ответа, а не дословное совпадение формулировок.

## Проверка интерфейса и нескольких вложений

- Выберите `01-specification.xlsx`: появился чип с именем. Нажмите крестик:
  файл удалён; при пустом сообщении отправка снова недоступна.
- Выберите `01-specification.xlsx`, `02-invoice.docx`, `05-product.jpg` и напишите:
  «Excel и Word содержат одну спецификацию, не суммируй повторы. Проверь позиции
  и скажи, есть ли среди них товар с фото». Все 3 файла должны отправиться вместе.
- Выберите сразу `01`, `02`, `03`, `04`: сообщение «не более 3 файлов».
- На ширине 320–375 px поле сообщения, кнопки и чипы помещаются на экране;
  крестик доступен, имя файла не растягивает форму.
- Для ограничения набранного текста вставьте длинный текст: поле ввода
  ограничено 1000 символами. Содержимое документа `08` учитывается отдельно.

## Проверка HTTP-ошибок без обращений к модели

С запущенным сервером выполните из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\docs\attachment-samples\check-api.ps1
```

Скрипт проверяет неподдерживаемое расширение, несовпадение MIME-типа, повреждённый
и пустой PDF, превышение 10 МБ и 4 файла в одном запросе. Он не отправляет
положительные сценарии в модель. Для другого адреса добавьте
`-BaseUrl http://127.0.0.1:8001`.

Один запрос вручную (PowerShell; используйте именно `curl.exe`):

```powershell
curl.exe -i -X POST http://127.0.0.1:8000/chat -F "files=@docs/attachment-samples/11-unsupported.txt;type=text/plain"
```

Ожидается **415**, тело содержит `reply` и `products: []`.
Для проверки MIME отправьте действительный PDF как JPEG:

```powershell
curl.exe -i -X POST http://127.0.0.1:8000/chat -F "files=@docs/attachment-samples/03-invoice.pdf;type=image/jpeg"
```

Тоже ожидается **415**. Расширение и `Content-Type` проверяются вместе.

## Что проверено при подготовке

Документы открываются соответствующими библиотеками; PDF содержит извлекаемый
русский текст; старый XLS читается; PDF из картинки не содержит текстового слоя.
Проверены 8000 символов, первые 10 страниц и размер большого PDF. Сводка проверки
загрузки этих конкретных файлов находится в `validation-results.json`.
В этой проверке агент подменён, поэтому она подтверждает обработку файлов и HTTP,
а качество ответов настоящей модели проверяется вручную описанными запросами.

Файлы и скрипт подготовлены локально; коммиты не выполнялись.
